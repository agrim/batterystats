# BatteryStats Bug Scan - 2026-06-29

## Scope

Post-patch scan of the BatteryStats app, widget, settings, menu bar controller, battery reading pipeline, widget persistence, refresh policy, alert/history plumbing, and tests.

Scan inputs:
- Listed all Swift files in `BatteryStats`, `BatteryStatsWidgets`, and `Tests`.
- Grepped for stale-state, timer, observer, force-cast, preference, widget, battery-age, input-power, and menu-bar patterns.
- Read the high-risk data and UI paths directly: `BatteryReadingService`, `SmartBatteryReader`, `PowerSourceReader`, `BatteryMonitor`, `BatteryWidgetSnapshotStore`, `BatterySnapshot`, `BatterySummaryGridView`, `MenuBarBatteryView`, `BatteryDashboardView`, `PreferencesStore`, `SettingsView`, widget views/provider, alert/history stores, and focused test suites.

## Confirmed Findings In The Implementation Batch

1. Menu bar battery display could ignore display preference changes.
   - Cause: status-item repaint and replacement needed explicit display-preference invalidation handling, including same-value picker commits and sibling preferences stores.
   - Fix status: implemented with menu-bar display invalidation, forced repaint, status-item reinstall when length/mode changes, and regression tests.

2. Menu bar panel could fail to appear from full-screen apps.
   - Cause: panel/window presentation needed active-space collection behavior and resilient foreground ordering without relying on normal app activation.
   - Fix status: implemented with full-screen auxiliary, active-space, nonactivating panel presentation, retry, and active-space reposition coverage.

3. Menu bar icon could show an empty/unknown battery despite valid charge data.
   - Cause: presentation fell back too aggressively when stored or public percent evidence was stale or missing.
   - Fix status: implemented by normalizing public/smart capacity evidence, repairing widget snapshots, and using a safer symbol fallback path.

4. Icon + percentage and other menu-bar display modes could lag or keep stale AppKit button state.
   - Cause: NSStatusItem content was not always fully reset and repainted after preference changes.
   - Fix status: implemented by clearing all title/image/tooltip state before applying new content and invalidating layout/display.

5. Widget stats could lag behind the main app.
   - Cause: energy probes could skip publishing when values were stable even though user-visible freshness had advanced.
   - Fix status: implemented by including the visible update minute in probe and widget reload signatures.

6. Battery age could be wrong or stale.
   - Cause: stored age components and noisy manufacture-date fields could be trusted too far.
   - Fix status: implemented by validating manufacture date, recomputing age from manufacture date plus snapshot/read date, rejecting future/implausible/orphan age, and ignoring known pack/manufacturer-data false positives.

7. Charger speed could show adapter capability instead of current inflow.
   - Cause: adapter maximum watts, negotiated power, and live input power are different signals and must not be conflated.
   - Fix status: implemented by preferring counter-backed/live system input power when trustworthy, rejecting exact adapter-capability echoes, and keeping adapter max separate from input power.

8. Main summary time row could show a naked current or wattage under a time label.
   - Cause: missing time estimates fell through to rate-only text.
   - Fix status: implemented as `Estimating / <rate>` so the row remains semantically clear.

9. Public `Battery Power` state could be overridden by stale `Is Charging` or `Is Charged` flags.
   - Cause: public power-source state and boolean flags disagreed after state transitions.
   - Fix status: implemented by letting explicit Battery Power suppress stale external-power inference.

10. Widget health could preserve stale stored health when valid capacity evidence was available.
    - Cause: snapshot sanitization preferred stored health before recomputing from full/design capacity.
    - Fix status: implemented by deriving health from valid capacity evidence first.

11. Thin green hairlines appeared below the two progress bars.
    - Cause: progress bar styling left a secondary underline/shadow artifact below each bar.
    - Fix status: implemented by removing that extra visual line while preserving the actual filled track.

## No New High-Confidence Unfixed Bugs Found In This Scan

The post-patch scan did not find another high-confidence runtime bug that should be changed before commit.

Reviewed areas without a new finding:

- Full-screen panel presentation now uses active-space collection behavior, nonactivating panel setup, foreground ordering, retries, and active-space repositioning.
- Battery age now has tests for packed-date decoding, future dates, implausibly old dates, stale stored age, widget age refresh, and manufacturer-data false positives.
- Charger-speed parsing now has tests for stale 100 W adapter reports, 70 W negotiated contracts, counter-backed live input power, and exact adapter-capability echoes.
- Widget freshness and sanitization now share the same presentation signatures as the main app for user-visible fields.
- Observer/timer cleanup paths were checked for obvious leaks, duplicate observers, missing cancellation, and timers stuck in the wrong run loop mode.
- Project inclusion was checked for new source and test files.
